# Antropolis

A canvas ant-colony game in one HTML page. Players grow a colony from a single queen: dig tunnels,
hatch ants, forage, fight raids, go deeper, and start again with a royal flight.

The live game is served by GitHub Pages from the `main` branch (`index.html` at the repo root).
The same files go into the Android app (see `.github/workflows/android.yaml`).

## Quick start

```sh
python3 tools/build.py              # build index.html, the-colony.html, sw.js and dev.html from src/
python3 -m http.server 8000         # then open http://localhost:8000/dev.html
python3 tools/lint.py               # ESLint over the joined script (needs eslint: npm install eslint)
python3 tools/test/check.py         # replay a fixed game session and compare with the baseline
```

`dev.html` is the same game with the preview tools turned on (a panel for jumping ahead, giving
food, starting raids and so on). It is not committed.

## Rules

1. **Edit `src/`, never `index.html`.** `index.html`, `the-colony.html` and the cache name in `sw.js`
   are generated by `tools/build.py`. Commit them after building, because Pages serves them as they are.
2. **The save must keep working.** Players' colonies are in `localStorage`. New save fields are
   optional (read them as `S.x || 0` or `S.x == null ? ... : ...`). Never bump `SAVE_VERSION`,
   never rename or remove a field (old renames are handled by `OLD_NAMES`). See `src/js/core/save.js`.
3. **Every change gets a build number.** Bump `BUILD` in `src/js/ui/settings.js` for each build
   you hand out. `APP_VER` is the player-facing version and only changes for public updates.
   The build script stamps the service worker cache (`colony-vNN`) from `BUILD` so phones pick up
   the new version.
4. **Tidy-ups must not change the game.** If a change is only meant to move or clean up code,
   `tools/test/check.py` must say "Identical to the baseline at every checkpoint". If a change is
   meant to change gameplay or visuals, run `check.py --record` afterwards and say so in the commit.
5. **Don't remove mechanics** without agreeing it first.

## How the code is laid out

All files in `src/js` are joined, in the order given by `src/js/ORDER`, into one `<script>` in
`src/index.html`. They share one global scope (plain `var` and `function`, no modules), so a
function in one file can call a function in any other. Top-level code that runs at start-up
lives in `main/boot.js`, which must stay last.

| Folder | What's in it |
| --- | --- |
| `core/` | helpers, game state `S` and player profile `P`, sound effects, saving, the run/flight reset, `tuning.js` (balance numbers for the newer systems) |
| `economy/` | counting ants, food, eggs and rewards, the colony tick, time-away earnings |
| `world/` | tunnel and chamber layout, the nest, camera, digging the tunnels |
| `ants/` | the queen, foragers, the worker crew, nurses, the army (soldiers, scouts, injured), hero ants |
| `threats/` | invader waves, termite raids, cave crickets, the Giant Mole |
| `layers/` | the deep layers: Larder, Armoury, Crystal Caves |
| `render/` | everything drawn on the canvas |
| `ui/` | HUD and tabs, info cards, daily gift and quests, shop, map, events, settings, intro, ads, music |
| `dev/` | the preview tools (only active in `dev.html`) |
| `main/` | touch input, the main loop, start-up |

Useful places to start:

- `core/helpers.js` starts with a description of every field of `S` (the colony) and `P` (the player profile).
- `ants/army.js` is the army's brain: `moveArmy` → `armyCounts` → `armyStep` per ant.
- `main/loop.js` is the frame loop (`frame`), and `drawT` there lists the drawing order.
- `core/tuning.js` is where to adjust balance after playtesting.

## Checks

- `tools/build.py --check` fails if the built files are out of date with `src/`.
- `tools/lint.py` lints the joined script. Functions only called from `onclick="..."` text are
  detected and treated as used.
- `tools/test/check.py` serves the repo, loads `dev.html` in headless Chromium with a fixed random
  seed and fake clock, plays a scripted session (waves, termites, digging, crickets, the mole, time
  away, a royal flight, every tab) and compares fingerprints of the game state, the page and the
  canvas at 15 checkpoints. Needs `pip install playwright && playwright install chromium`.

GitHub runs the build check and lint on every push and pull request (`.github/workflows/check.yaml`).

## Releasing

1. Work on a branch, open a pull request into `main`.
2. Bump `BUILD`, run `tools/build.py`, `tools/lint.py` and `tools/test/check.py`.
3. Merge into `main`. GitHub Pages publishes it within a minute or two; players get it on their
   next visit (the service worker cache name changes with `BUILD`).
4. For the Android app: Actions → "Build Android app" → Run workflow.
